# From-scratch dense versus hierarchical study

Approved next step: check hierarchical learnability, pretrain both architectures fairly on English, then evaluate binding/retention/runtime before considering a Transformer baseline. Keep architecture and routing unchanged.

Two modes only: dense and hierarchical, eight width64 GRUs, fixed graph/sum readout, four groups/two children for routing, seed42. Shared base parameter initializations match exactly; hierarchical has its existing 1,548 router parameters and balance coefficient0.01. Soft execution remains dense. This is token/update matched, not exactly parameter/compute matched.

1. Training-only learnability probe: fresh random state for each mode, LR0.003, batch4/unroll128. Train the first existing gradual-data group for500 updates, then first four groups for500 additional updates, carrying optimizer state. Record initial/500/1000 train ranking and fixed raw samples. No held-out claim, checkpoint selection or source transfer into pretraining. Failure at this finite budget is not an architecture impossibility result.
2. Independently initialize both modes again from seed42; do not load probe weights. English full-document pretraining: same cached1000 train/32 development stories, LR0.001, batch4/unroll128, 4,000 updates and development evaluation every500. Include routing auxiliary only in hierarchical gradient objective; language evaluation remains pure cross-entropy. Select minimum English development loss with initial eligible. Save initial/latest/best, optimizer and stream/carry provenance. Dedicated driver is fresh-only, not a resume implementation.
3. Fresh balanced binding data seed631204 (same verified confirmation generator). Train each mode from its own development-selected English checkpoint using hierarchy_run, fresh optimizer, 1,000 QA +1,000 English updates, evaluate every250 QA cycles. Same task/English streams, LR0.001. Select macro eight-condition known/new-name development correctness, then pure QA loss, initial eligible. English monitored separately. No warm-start mismatch between update modes.
4. Freeze/check hashes and lock both English and task-selected checkpoints before test. Score English pretraining and adapted English retention, fresh known/new-name binding with zero filler, and separate64/128-byte neutral-filler test probes (same fact assignments, no delayed training). Require all eight conditions including sentence order. Delayed failure cannot diagnose extra forgetting if zero-delay binding already fails. These are one-seed shared-grammar diagnostics, not chat competence.
5. After training ends, benchmark selected English models sequentially in fresh processes: warmed JIT forward pass, batch1, lengths32/128/512, 5 warmups and30 timed repetitions; compile time reported separately. Report parameter and optimizer tensor bytes, persistent recurrent state bytes, and peak process RSS including JAX/compilation overhead. Timings exclude text I/O and are not generation latency, sparse dispatch, Transformer, device-portability or scaling evidence. Fixed seeded inputs and environment are recorded.

Tests: fresh-only driver/output guards, no supervised-span misuse, source and initial shared-weight identity, stream coverage/steps/counters, selected checkpoint, finite routed updates and runtime artifact schema smoke. Reuse existing routing/binding/evaluation tests. Freeze configs/data/source/code before relevant phases. Preserve prior source/checkpoints; save all negative outcomes and update research/PRD/README. No sweeps or test-based model choices. A direct Transformer comparison remains unjustified unless useful capabilities are demonstrated; this study cannot establish replacement.
