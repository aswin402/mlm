# Balanced binding confirmation and explicit English rehearsal

Authorized next research step: fix the discovered pair-role imbalance, increase name diversity, keep the sum-readout graph unchanged, and explicitly test retention. This is a fresh experiment, not a silent replacement of the previous test.

Generate 64 deterministic three-letter pronounceable entity labels: 32 training, 16 new development, 16 new test. Role A/B classes are random offline strata, never model inputs. Training uses 64 entity pairs from two within-role cycles and two cross-role matchings, excluding held-out familiar-name development/test pairs. All training names have four partners; 32 pairs are within-role and 32 cross-role. Each pair gets two disjoint color pairs covering all four colors and both sentence orders. Training has 256 four-question groups / 1,024 documents. Each familiar-name evaluation pool uses 16 disjoint pairs covering all 32 training names, half within-role and half cross-role. New-name pools use eight pairs covering all 16 new names, also balanced. All six color pairs and both sentence orders are evaluated. Development/test pairs and exact text are disjoint; new-name pools are disjoint. Names are not guaranteed globally unseen in English pretraining.

Use runs/english-v1/best.mlm (original English graph) as the common source, fresh optimizer, seed 42, LR 0.001, batch four, unroll 128. Source is intentionally different from the prior memorization source: this study asks whether a clean English model can acquire binding while retaining its English. Comparisons with prior runs cannot isolate dataset balancing alone.

Both arms receive the same 2,000 complete-group QA updates in the same sampler order. Task-only gets those 2,000 optimizer updates. Rehearsal interleaves one full-document English training-stream chunk after each QA update, for 4,000 optimizer updates total. Adam state is shared across the two objectives in the rehearsal arm; recurrent state is separate, with independent QA resets and English stream carry detached across chunks. This matches task exposure, not total compute, input bytes, or update count. Both losses are mean target cross-entropy per batch; alternating steps are not a guarantee of equal gradient contribution. No story targets are secretly mixed into QA documents.

Evaluate at initial state and every 500 QA updates. Primary binding measure: macro-average of complete eight-condition correctness across familiar-name and new-name development buckets, each including both fact orders; target QA loss breaks ties. Save best-task.mlm without an English constraint. Save best.mlm only when English development loss <=1.25 times the initial English development loss, using the same binding/loss ordering. Initial state is eligible and provides the protected fallback. English TEST is not opened until checkpoint locks; development is used for the retention constraint. Report selected steps, task and total optimizer counts, actual per-objective bytes/chunks, and source identity. No resume support claimed; refuse nonempty output directories.

Freeze data/config/source/code hashes before training and lock all selected checkpoints before testing. Report protected and unconstrained checkpoints separately, identify step-zero fallbacks explicitly, and score familiar/new-name and within/cross strata. Use untouched new task test samples and the reused English test as a retention diagnostic. Record raw greedy samples separately from neural candidate ranking. One seed, artificial names, four colors and shared grammar do not establish broad language understanding. No hyperparameter sweep or architecture change.

Tests cover balanced partition counts, degree/partner coverage, pair/text/name disjointness, all eight conditions and unroll/mask bounds, protected selection, source preservation, objective counters and fresh-output guard. Implement confirmation_data.py and confirmation_run.py using existing neural training/scoring utilities. Save results and update research/PRD/README with actual outcomes and limitations.
