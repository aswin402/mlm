For these two selected memory initializations, acquisition follows the combined training schedule. Both initializations reach16/16 training rankings and4/4 complete groups with schedule42; both reach8/16 and0/4 with schedule43. The new crossed run initialization43/schedule42 succeeds, while initialization42/schedule43 fails. Thus initialization43 can acquire the narrow task under the successful schedule.

This is an exploratory post-hoc completion of a2×2 table with reused historical diagonals, not independent replication or a general causal finding. QA ordering and English rehearsal document exposure/order still vary together. Generalization remains unestablished: every cell completes zero tiny development groups.

## Design and isolation

The reviewed [plan](../../archive/README.md#historical-plans), [revision2 protocol](../../evidence/addressing-factorial/protocol.json), configs, scripts and inputs were frozen before either new run. The first protocol draft was strengthened after review and before training, and remains as `protocol-before-review.json`; factor levels, budgets and contrasts did not change. The grid uses memory initialization seeds42/43 and combined schedule seeds42/43. These levels were chosen after observing the diagonal42/42 success and43/43 failure, so selection bias and historical/new execution limits remain explicit.

Memory initialization comes from each historical run's **step-zero** initial checkpoint, never its trained endpoint. The unchanged `warm_start` copies every tensor, including memory, into a fresh optimizer under the target schedule config. Every non-memory tensor (all graph/node/router/embedding/output parameters, not just the shared learning-rate role) exactly matches the same original English checkpoint. Seven added memory tensors have matching shapes, random kernels differ across initializations, and the memory output gain begins at zero. Preflight confirms every crossed initializer tensor and fresh optimizer state, and initial parameter fingerprints match their intended historical initialization.

The target config seed controls complete-group selection/order and the English stream (seed+1). All four groups are selected in every run, so QA membership is fixed. Schedule42 means QA RNG42 and English RNG43; schedule43 means QA RNG43 and English RNG44. English ordering changes which document bytes occur within the bounded budget as well as their order. It is a combined training schedule factor, not an isolated QA-order or replay-order factor.

Each new run independently receives2,000QA+2,000English updates,4000 optimizer steps, exactly500 presentations of every training group. New work totals8,000 optimizer updates. No budget extensions, replacement cells, checkpoint selection, new test files, trained readout ablation or model promotion occurred. Architecture, inference, optimizer, training-step math, scoring and dataset-generation code are unchanged. The task remains16 records for two names and two color pairs, both fact orders, both queries and complementary assignments.
